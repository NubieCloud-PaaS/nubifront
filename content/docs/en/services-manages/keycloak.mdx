**Keycloak** is an identity server: it handles authentication, SSO and user accounts for your applications, through the **OIDC** and **SAML** protocols. Your applications delegate sign-in to Keycloak instead of managing passwords and sessions themselves.

Unlike the other managed services, Keycloak is an **application**: it has a **public URL** and an admin console you reach from a browser.

## What sets it apart

| | Databases and message queues | Keycloak |
|---|---|---|
| Access | internal to the project | **public URL** |
| Storage | dedicated volume | **none** — everything lives in a PostgreSQL |
| Credentials | chosen by you | **generated**, shown once |

## Prerequisite: a managed PostgreSQL

Keycloak does not bundle its own database. It stores your **realms**, **users**, **clients** and **signing keys** in a [managed PostgreSQL](/en/docs/services-manages/reference#postgresql) that you pick — and that stays yours, with its backups, its SQL console and its metrics.

Before deploying Keycloak you therefore need **a managed PostgreSQL in the same environment**. If there is none, create it first.

> ℹ️ The PostgreSQL must be **in the same environment** as Keycloak. A PostgreSQL from another environment will not appear in the list.

Nubiecloud automatically creates a dedicated database for this Keycloak on it. It then shows up in your SQL console alongside your other databases.

## Deploying Keycloak

Under **Deploy an application → Managed services → Keycloak**:

| Field | Required | Default | Notes |
|-------|:--------:|---------|-------|
| **Name** | ✅ | — | lowercase, DNS format |
| **Host PostgreSQL** | ✅ | — | a managed PostgreSQL from the same environment |
| **CPU / RAM** | ✅ | 0.5 core / 1.5 GB | within the project quotas |
| **Replicas** | ✅ | 1 | a single instance for now |
| **Custom domain** | ✕ | — | served in addition to the generated address |

There is **no password to enter and no storage to size**: the administrator account is generated by the platform, and Keycloak uses no volume.

Some PostgreSQL instances may appear **greyed out** in the list, with a reason. Those were created with an earlier version of the model and do not allow the required administrative operations. Create a new one, or contact support.

## The administrator password

At the end of the deployment, the console shows **once**:

- the address of the admin console,
- the username, `admin`,
- the generated password.

> ⚠️ **Write this password down before closing the dialog.** The console does not show it again. If you lose it, contact support.

Once signed in, change it from Keycloak: **Users → admin → Credentials**. The account created at deployment is a bootstrap account.

The first start takes **two to three minutes**: Keycloak initialises its database schema before answering. An error page during that window is expected.

## Connecting an application

Once Keycloak is live, create a *client* in its admin console, then configure your application with the following addresses — replacing `my-realm` with your realm:

```
Issuer      https://YOUR-KEYCLOAK.apps.nubiecloud.io/realms/my-realm
Discovery   https://YOUR-KEYCLOAK.apps.nubiecloud.io/realms/my-realm/.well-known/openid-configuration
```

Most OIDC libraries only ask for the discovery URL: they derive the authorization and token endpoints from it.

### Custom domain

You can serve Keycloak on your own domain, in addition to the generated address.

> ⚠️ Tokens are still issued on **the generated address**. That is the one to configure in your applications, not your custom domain. It is written into every token issued: it never changes.

## Backing up

Keycloak's data is its PostgreSQL's data. **Backing up that PostgreSQL backs up your Keycloak** — enable its automatic backups and see [Backups & restore](/en/docs/backups/restaurer).

## Deleting

> 🚨 Deleting a Keycloak **also destroys its database** on the host PostgreSQL. Realms, users, clients and signing keys are permanently lost, and applications that authenticate through this Keycloak stop working.

The confirmation dialog names the database and its PostgreSQL. To guard against an accidental click, turn on **deletion protection** on the deployment page: deletion is then refused until you lift it.

The host PostgreSQL itself is not deleted: only this Keycloak's database and its user are. Your other databases on that cluster are untouched.

## Current limits

- **A single instance.** Keycloak runs as one instance; high availability is not offered yet.
- **A single version**, kept up to date by the platform.
- **Upgrades cause a brief outage**, while Keycloak migrates its schema.

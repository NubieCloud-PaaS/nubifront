Les **services managés** sont des briques d'infrastructure prêtes à l'emploi (bases de données, cache, file de messages) que vous déployez **comme une application**, dans un environnement, et que vos applications consomment via le réseau interne du projet.

## Services disponibles

| Service | Usage | Port | Sauvegardes | Console SQL |
|---------|-------|:----:|:-----------:|:-----------:|
| **PostgreSQL** | Base relationnelle (HA possible) | 5432 | ✅ | ✅ |
| **MySQL** | Base relationnelle | 3306 | — | — |
| **Redis** | Cache / clé-valeur | 6379 | — | — |
| **RabbitMQ** | File de messages (AMQP) | 5672 (UI : 15672) | — | — |
| **Kafka** | Journal de messages distribué | 9092 | — | — |
| **Keycloak** | Identité, SSO (OIDC / SAML) | URL publique | via son PostgreSQL | — |
| **n8n** | Automatisation de workflows | URL publique | via son PostgreSQL | — |
| **Metabase** | Tableaux de bord et analyses | URL publique | via son PostgreSQL | — |
| **Hasura** | API GraphQL sur vos bases | URL publique | via son PostgreSQL | — |
| **DocuSeal** | Signature électronique | URL publique | via son PostgreSQL et son bucket | — |
| **Open WebUI** | Chat sur vos modèles de langage | URL publique | via son PostgreSQL et son bucket | — |
| **Open Bank Project** | API bancaire ouverte (PSD2, Open Banking) | URL publique | via son PostgreSQL | — |

> ℹ️ **PostgreSQL est le service le plus complet** : haute disponibilité Blue/Green, sauvegardes automatiques vers le stockage objet, et [console SQL intégrée](/docs/services-manages/reference#console-sql). Les autres services sont déployés en instance simple. **Kafka** se déploie en 1 ou 3 réplicas — voir [Kafka](/docs/services-manages/reference#kafka).

> ℹ️ **Sept de ces briques sont des applications**, pas des services : **Keycloak**, **n8n**, **Metabase**, **Hasura**, **DocuSeal**, **Open WebUI** et **Open Bank Project** s'ouvrent dans un navigateur à une URL publique, n'ont pas de port à connecter, et rangent leurs données dans un PostgreSQL managé qui reste le vôtre. **DocuSeal** et **Open WebUI** y ajoutent chacun un bucket [NubiS3](/docs/services-manages/reference#docuseal) — documents signés pour l'un, fichiers téléversés pour l'autre — créé et supprimé avec l'application.

> ⚠️ **[Open WebUI](/docs/services-manages/reference#open-webui) exige un PostgreSQL portant l'extension `vector`**, et cette extension ne se pose qu'à la création de la base. Un PostgreSQL existant qui ne l'a pas ne pourra pas l'héberger : la console grise alors le choix plutôt que de laisser le déploiement échouer plus tard.

> ⚠️ **[Open Bank Project](/docs/services-manages/reference#open-bank-project) n'a aucun administrateur au démarrage**, et s'inscrire soi-même sur son adresse ne donne aucun droit. Le compte d'administration se crée **depuis la console**, sur la fiche du déploiement — c'est le seul chemin.

> ℹ️ **MongoDB n'est plus proposé au catalogue.** Les instances déjà déployées continuent de fonctionner et restent visibles dans la console.

## Fonctionnement commun

- Chaque service est déployé **dans un environnement** d'un projet, au même titre qu'une application.
- Il reçoit un **nom d'hôte interne** stable de la forme `nom-du-service-xxxx-internal`, joignable par les **autres applications du même projet/environnement**.
- Les **identifiants** (utilisateur, mot de passe, base) sont définis au déploiement et conservés de façon chiffrée — ils ne transitent jamais en clair par l'API.
- L'accès est **interne au cluster** (pas d'exposition publique directe d'une base).

## Connecter une application à un service

Le principe est toujours le même (illustré dans l'[étape 10 du Quickstart](/docs/quickstart)) :

1. **Déployez le service d'abord** (ex. PostgreSQL).
2. Sur la page du service, **récupérez la chaîne de connexion** (hôte interne, port, base).
3. **Ajoutez-la dans les variables d'environnement** de votre application (ex. `DATABASE_URL`).
4. (Re)démarrez l'application.

> ⚠️ Le câblage est **explicite** : Nubiecloud déploie le service, mais c'est vous qui copiez la chaîne de connexion vers votre application.
